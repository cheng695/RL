# 2026-10-20 轮速振荡与速度跟踪排查总结

## 1. 最终结果与证据范围

修改轮速目标变化率限制并加入最终轮速目标变化惩罚后，用户重新从头训练，测试反馈：vx 跟踪明显改善，可以较好跟随命令。

这次改善来自从头训练，不能解释为旧策略经过续训后逐渐修正。已有数据能确认旧策略的目标轮速频繁反向；目前尚无新策略的同工况 CSV 定量对照，也没有分别移除某项修改的对照实验，因此无法单独确定变化率限制、平滑奖励及其他训练配置的贡献。

现阶段保留原有 vx 跟踪奖励，以本次成功训练作为基线。旋转时的 roll、yaw 跟踪，以及不同高度和速度下的表现仍需分别评估。

## 2. 出现的问题

- 高度跟踪已学会，劈叉和 pitch 姿态有改善。
- 前进或后退命令下，机器人几乎原地不动，轮子反复抖动。
- 旋转不顺滑，实际 yaw 角速度跟不上命令；用户观察旋转时 roll 可达 7～10°。
- 增加低速样本、提高直行占比后，旧策略仍出现明显轮速振荡。

训练日志中的速度误差支持“运动跟踪仍较差”的判断，但平均奖励会混合站立、直线、转向等样本，不能代替固定命令测试。

## 3. 如何判断问题

### 3.1 区分动作限幅与力矩限幅

训练日志的 `wheel_action_at_limit_fraction` 检查策略动作是否达到配置的动作边界。曾观察到约 0.32%，只能说明轮子动作很少顶到动作上限。

它不能证明执行器力矩很少达到上限。当前速度驱动阻尼为 5.0，单轮力矩上限为 4.5 N·m，即使策略动作幅值不大，也可能因目标与实际轮速的误差而产生较大力矩需求。

诊断 CSV 的 `tau_estimate_nm` 来自隐式执行器的 `robot.data.applied_torque`；它是估计值，不能当作电机实测力矩或 PhysX 求解器真实力矩。对应的 `estimated_effort_at_limit` 也仅表示估计值达到配置限值的 99%。

### 3.2 记录完整控制链

新增 `play.py --motion_trace_csv`，每个控制步记录 env0：

1. 策略原始动作及动作项收到的动作。
2. 限速后最终下发的目标轮速、腿部目标角度。
3. 实际轮速、关节角度和估计力矩。
4. 目标与实际 vx/yaw、机体 roll/pitch、高度。

自动 reset 帧标记为 `state_valid=0`，分析时排除，避免混入重置后的状态。记录频率为控制频率，不能排除物理子步内发生的振荡。

- 命令：vx = +0.2 m/s，yaw = 0 rad/s，高度 = 0.30 m。

## 4. 采取的修改

### 4.1 先前实施的训练调整

| 配置 | 当前设置 |
|---|---|
| 站立 / 直线 / 原地转向 / 行进转向 | 20% / 60% / 10% / 10% |
| 非站立样本内部模式权重 | 0.75 / 0.125 / 0.125 |
| 前进 / 后退采样 | 各 50% |
| 带平移命令的幅值分布 | 60% 在 0.08～0.5；25% 在 0.5～1.0；15% 在 1.0～2.0 m/s |
| vx、yaw 总范围 | −2～2 m/s；−5～5 rad/s |
| 高度命令 | 0.25～0.35 m，每回合采样一次 |
| 额外直线 pitch 惩罚 | `straight_pitch_penalty.weight=0` |

通用姿态约束仍然启用。这些设置构成当前训练背景，不能将后续成功全部归因于其中一项。

### 4.2 降低轮速目标变化率

将 `wheel_joint_vel.max_velocity_rate` 从 400 降至 100 rad/s²。

目标限速公式为：

\[
\omega_{cmd,t}=\omega_{cmd,t-1}+\operatorname{clip}
(\omega_{target,t}-\omega_{cmd,t-1},-a_{max}\Delta t,+a_{max}\Delta t)
\]

当前控制周期 0.02 s，单步目标变化上限由 8 降至 2 rad/s。旧记录中每步平均变化约 7 rad/s，说明原有上限允许很大的目标跳变。

这是对控制过程的修改，也会影响平衡恢复和起步响应；100 rad/s² 是本轮实验参数，尚未根据真实硬件辨识确认。

### 4.3 惩罚最终下发目标的变化

新增 `wheel_target_smooth`，权重 −0.1：

\[
r_{smooth}=-0.1\cdot\operatorname{mean}_{L,R}
\left(\frac{\omega_{cmd,t}-\omega_{cmd,t-1}}{2.0\ \mathrm{rad/s}}\right)^2
\]

实现中的平方均值上限为 4.0，并对非有限数值进行处理。以上为奖励管理器乘时间步长前的表达式。

- 目标差分由轮子动作项保存，在缩放及变化率限制之后计算。
- reset 时按环境清零历史，避免跨回合计算变化。
- 稳定的非零轮速目标不会持续产生这一惩罚。
- 原有原始动作二阶差分惩罚继续保留。
- 观测维度未变，现有 checkpoint 的网络结构仍兼容。

### 4.4 从头训练并测试

用户采用从头训练，并反馈 vx 跟踪明显改善。实际成功实验的具体训练目录和 checkpoint 尚未在本记录中提供，应与训练生成的 `params/env.yaml`、`params/agent.yaml` 一同保存，便于后续复现。

示例命令如下；不添加 `--resume` 或 `--checkpoint`：

```bash
python Wheel-Leg/scripts/rsl_rl/train.py \
  --task MyRobot-Velocity-Flat-v0 \
  --num_envs 1024 \
  --max_iterations 3000 \
  --run_name wheel_target_smooth_scratch \
  --headless
```

## 5. 如何理解原因，以及是否修改 vx 奖励

现有 vx 跟踪包含权重 4.0、sigma=0.35 的高斯正奖励，以及权重 −1.2、beta=0.3 的 Huber 惩罚。命令为 0.2 m/s、实际为 0 时，两项合计约 +2.81；准确跟踪时为 +4，均未乘时间步长。

这个数值表明当前奖励对小速度误差较宽容，但它本身不能证明策略偏好不动。策略优化的是所有奖励组成的长期回报；高斯项绝对值较高，也不能直接推导出“不动是全局最优”。PPO 不直接对奖励函数的速度导数反向传播，也不保证有限训练找到全局最优策略。

曾讨论过将静止表现作为基准、重新归一化高斯奖励的方案，但该方案没有实施。当前 vx 奖励在本轮振荡修正中未改变，而从头训练已经取得明显改善，因此没有充分证据要求继续修改 vx 奖励。

较合理的解释是：减少目标跳变并约束目标变化，有助于策略在训练初期形成持续驱动，降低陷入振荡行为的可能性。这仍是解释性假设；两项同时修改、从头随机训练，尚不能证明单一因果关系。

## 6. 解决效果与后续检查

| 项目 | 当前结论 |
|---|---|
| 旧策略目标轮速频繁反向 | CSV 已确认 |
| 修改后从头训练的 vx 跟踪 | 用户测试反馈明显改善，可较好跟随 |
| 新策略反向次数、速度 MAE 是否定量下降 | 待同工况新 CSV 验证 |
| 旋转 roll 与 yaw 跟踪是否改善 | 尚未确认 |
| 哪一项修改贡献最大 | 未做分别移除修改的对照实验 |

代码侧完成了 11 项 CPU 检查，覆盖目标差分、恒定目标零惩罚、reset 历史及既有奖励数值检查；这些检查不验证物理行为或训练收敛。

建议用新旧策略分别测试 vx=±0.2、±0.5、±1.0 m/s，并覆盖 0.25、0.30、0.35 m 高度；转向工况单独记录 yaw 跟踪与 roll。比较速度 MAE、目标反向次数、目标变化幅度、姿态和失败次数，防止只改善平滑度却损失运动能力。

训练与 play 共用当前控制配置，因此现在播放旧 checkpoint 也会使用 100 rad/s² 限制。原始 `before_forward_02.csv` 属于旧限制下的基线，应保留；新文件使用不同名称。严格复现实验需要匹配训练配置与代码版本。
