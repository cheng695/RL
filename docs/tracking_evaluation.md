# 固定命令评估与训练指标

## 自动评估

在仓库根目录运行，替换 checkpoint 路径：

```bash
conda activate env_isaaclab
python Wheel-Leg/scripts/rsl_rl/play.py \
  --task MyRobot-Velocity-Flat-Play-v0 \
  --num_envs 1 \
  --checkpoint "/path/to/model.pt" \
  --eval_tracking --headless
```

去掉 `--headless` 可以观察仿真。评估不启用键盘和交互 HUD，自动完成后退出。
不要同时传入 `--command_vx`、`--command_yaw` 或 `--command_height`。

默认依次评估五组命令，偏航速度均为零：

| 测试 | 前进速度 m/s | 底盘高度 m |
| --- | ---: | ---: |
| height_low | 0 | 0.25 |
| height_mid | 0 | 0.30 |
| height_high | 0 | 0.35 |
| reverse | -0.2 | 0.30 |
| forward | 0.2 | 0.30 |

每组独立重置 3 次，每次先等待 2 秒，再记录 8 秒，默认共 150 秒仿真时间。
用 `--eval_trials`、`--eval_settle_s`、`--eval_measure_s` 调整。
保持非轮子接触、姿态及机械约束终止条件；提前终止结束当前试次并记录结果。
不把自动 reset 后的初始状态算入测试数据。误差包含失败试次在失败前的有效样本，
因此必须同时查看 `failed_trials` 和 `complete_trials`，不能只比较存活段误差。

输出目录默认为 `logs/tracking_eval/<时间戳>/`，也可用 `--eval_output` 指定一个尚不存在的目录：

- `samples.csv`：每个测量步的目标速度、实际速度、目标高度、实际高度。
- `report.json`：逐试次状态、逐组误差和实际值均值、响应增益。
- `env.yaml`、`agent.yaml`：本次评估使用的配置。

评估使用当前任务配置、确定性策略和关闭观测噪声的 Play 环境。
仍保留该任务的初始状态及启动随机化；三个重复试次只提供初步诊断。
旧 checkpoint 不会自动恢复其原训练配置，比较不同策略时应保持评估配置一致；
复现旧策略原始表现时需先恢复对应动作 scale、控制方式和资产配置。

高度采用训练奖励使用的 chassis 刚体世界 Z，适用于地面 Z=0 的当前平地场景。
修改奖励权重不会改变这里的物理误差指标。

## 如何解读

- `vx_mae_mps`：速度平均绝对误差；`speed_xy_mps` 在零命令时反映漂移/来回摆动。
- `height_mae_cm`：高度平均绝对误差；`height_bias_cm` 为实际减目标，负值表示偏低。
- `height_response_gain`：高、低高度测试实际高度均值之差除以 0.10 m。
  接近 0 表示高度几乎不随命令改变，接近 1 表示响应幅度接近要求；仍需检查偏差。
- `velocity_response_gain`：前进、后退测试实际速度均值之差除以 0.4 m/s。
  接近 0 表示没有明显区分正反向命令，接近 1 表示响应幅度接近要求。
- 只有相关两组的所有试次完整完成时才输出对应响应增益。
- 测试窗口不足或全部提前失败时，误差可能缺失；缺失不代表误差为零。

先看失败次数，再看实际值是否随命令改变，最后比较误差。
如果原地高度几乎不响应，再考虑单独的原地高度训练分支；避免同时修改多项奖励和控制参数。

## 训练指标修正

命令模块在 reset 时额外输出每个分组的数值总和及样本数。
`train.py` 在 RSL-RL 写日志之前，按本次日志窗口内完成回合的数据汇总，
用总和除以总样本数，替代原来对各 reset 批次均值的直接平均。

该修正覆盖高度 low/mid/high、速度各模式以及静止指标。
空分组只输出零样本数，不输出虚假的零误差；样本数现在是窗口总数。
静止路程按含静止样本的回合数加权，其他分组误差按环境步样本数加权。
未结束回合的数据会在之后 reset 时进入统计，这些指标不是当前 rollout 全部状态的快照。

修正只对重新启动的训练进程生效，不修改已有 TensorBoard 日志。
普通奖励项及策略更新不受这次日志汇总修正影响。
